## 1. 项目速览

- 定位：**微信登录库**（crate `pek-wechat`，edition 2024），非服务、无面板。
- 参照：`G:\Code\Pek.FrameWork\DH.SKIT.FlurlHttpClient.Wechat`（`DH.SKIT.FlurlHttpClient.Wechat.Api` 的 `Sns` 族）。
- 远程仓库：`https://github.com/RemoteAll/Pek.Wechat.git`（remote 名 `main`，分支 `main`；与生态其他仓库一致）。
- 企业微信推送：`dhrust::wecom`（DH.RustBase 已有），本 crate `pub use` 转发为 `pek_wechat::wecom`。

## 2. 常用命令（构建 / 测试 / 回归）

```powershell
cargo check
cargo test
cargo clippy --all-targets
cargo run --example qr_login_url
# 交叉检查（可选）
cargo zigbuild --target x86_64-unknown-linux-musl --lib
```

- 日常写码用 `cargo check`；需要二进制时 `cargo build --profile fast`；`--release` 只用于发布。
- 依赖下载走项目内 `.cargo/config.toml`（rsproxy 镜像）。
- **改 `res/Wechat.toml.template` 后需 touch 所属 `.rs`**（`include_str!` 不触发重编）。

## 3. 目录约定

```
src/lib.rs          # 模块声明 + 顶层再导出 + 使用文档
src/error.rs        # WechatError（Config/Http/Api/Json；is_token_invalid）
src/oauth.rs        # 授权地址构造（qrconnect / oauth2 authorize）+ state 生成/常量时间校验
src/sns.rs          # Sns 模型（OAuthToken/WechatUserInfo/WechatLogin/JsCode2Session/AccessTokenInfo）
src/client.rs       # WechatClient（单账号）：GET+JSON 信封、重试、全局令牌缓存
src/settings.rs     # Config/Wechat.toml（[[Accounts]]）+ 账号选择
src/wechater.rs     # Wechater 统一入口（配置驱动）
res/Wechat.toml.template
examples/{qr_login_url,login_once}.rs
tests/sns_e2e.rs    # 本地 HTTP 桩：请求契约 + 缓存/错误分支
docs/{决策记录,项目记忆,项目接续指南,用户档案}.md
tools/continuity/*
```

## 4. 关键契约（改动前先看）

- 授权地址：`connect/qrconnect`（`snsapi_login`）/ `connect/oauth2/authorize`（`snsapi_base|snsapi_userinfo`），
  末尾必须 `#wechat_redirect`，`redirect_uri` 整体 URL 编码。
- 接口：`/sns/oauth2/access_token`、`/sns/oauth2/refresh_token`、`/sns/userinfo`、`/sns/auth`、
  `/sns/jscode2session`、`/cgi-bin/token`。
- 错误码：响应 `errcode != 0` → `WechatError::Api`；令牌失效码 40001/40014/42001/42002/42007/42009。
- 全局令牌缓存：`expires_in - 120s`；锁内串行刷新（单飞）。
